# Non-functional design notes


- **Scale and latency:** 200k files/day is about 2.3 files/second on average; 400k/day is about 4.6. Size workers by observed processing time, file size, and arrival distribution, not daily averages alone. Autoscale on queue age and depth; cap concurrency by memory and DB quotas. A 15-minute p95 budget includes notification, queue wait, processing, and staging/MERGE. Use a short microbatch cadence and load-test burst distributions. Local timings do not prove this SLA.
- **Onboarding:** versioned profiles and dictionaries support configuration-only onboarding. A one-day target assumes documented source schemas and timely domain review. Multiple schema profiles support explicit versions and metadata predicates; ambiguous matches and unknown versions are rejected. Formal schema validation remains future work.
- **Reliability:** isolate each file, retry transient faults, and preserve dead-letter payloads. Multi-zone managed services support the availability objective; no 99.5% claim is made for a laptop. Worker scaling may be limited by storage and queue contention; linear scaling must be measured.
- **Governance:** retain immutable source links and config versions, encrypt data in transit and at rest, tokenise patient identifiers, scope IAM, and apply retention rules. Name-resolution coverage is distinct from correct clinical interpretation. Monitor unresolved names by clinic and update reviewed dictionaries toward the 98% target; the prototype does not meet that target.
- **Observability:** expose throughput, error rate, queue age, end-to-end p95 latency, deduplication counts, and mapping coverage. Alert above a 1% processing error rate with a minimum-volume window, or when queue age threatens the SLA. Production Cloud Monitoring receives these signals; the local API exposes a small `/metrics` endpoint and structured logs. The local Operations tab measures queue lag and file p95 and persists threshold transitions with acknowledge/recover actions. External notification delivery remains a production integration.

Architecture source is also available as editable Mermaid in `architecture.mmd`. Main trade-off: a small deterministic local service is easy to run and inspect; production queueing, identity, governance, and warehouse loading are separate deployment concerns. No generative model is required in the transformation path.
